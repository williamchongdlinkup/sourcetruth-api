Overview

SourceTruth is a pre-indexed, multi-tradition canonical text API. Instead of building and maintaining your own RAG pipeline over religious, philosophical, and classical texts, you query SourceTruth's production search infrastructure directly.

Two primary endpoints:

  • /v1/search — hybrid semantic + keyword retrieval. Returns ranked passage chunks with metadata. Available to all tiers including free.
  • /v1/answer — grounded Q&A: retrieves relevant passages then generates a cited answer via Claude. Paid tiers only.

Search uses voyage-multilingual-2 embeddings with per-corpus tuned reranking (MMR, text deduplication, or dense RRF) derived from LLM-judged retrieval evaluation. Cross-lingual queries work: ask in English, retrieve Pali, Arabic, Sanskrit, Classical Chinese, and Gurmukhi texts.

Authentication

All endpoints that require authentication accept an API key in the X-API-Key HTTP header. The /v1/corpora, /health, and /v1/keys endpoints are public and require no key.

Header format
X-API-Key: st_your_api_key_here

API keys are prefixed with st_. Keys are hashed with SHA-256 before storage — the raw key is never stored and cannot be recovered. Store it securely at the time of issuance.

Key management There is currently no self-service key rotation endpoint. If you lose your key, issue a new one via POST /v1/keys. Contact support if you need to deactivate a compromised key.

Rate Limits

  • Search: 60 requests per minute per IP address
  • Answer: 20 requests per minute per IP address
  • Key creation: 5 per hour per IP address
  • Daily quotas: applied per API key (not per IP), reset at UTC midnight

When a rate limit is hit the server returns 429 Too Many Requests with a Retry-After header. When the daily quota is exhausted the server returns 429 with "Daily request limit reached."

API Reference

Search

POST /v1/search All tiers • Auth: optional (anon allowed, unauthenticated calls share global quota)

Hybrid semantic + keyword search using voyage-multilingual-2 embeddings with per-corpus reranking. Returns up to top_k ranked passage chunks.

Request body

FieldTypeDefaultDescription
querystringrequiredFree-text search query. English queries work across all traditions including non-English corpora.
corpus_codesstring[]nullExact corpus codes to search. Most precise scoping. See corpus table.
traditionsstring[]nullTradition names. Less precise than corpus_codes — searches all corpora in the tradition.
languagesstring[]nullISO 639-1/3 language codes: en, ar, pi (Pali), zh, sa.
collectionsstring[]nullCollection name filter (corpus-specific grouping).
top_kinteger8Maximum number of passages to return (1–50).
Scope precedence Filters stack with AND logic. corpus_codes is the most specific filter and takes priority for rerank mode selection. You can combine scopes: e.g. corpus_codes=["quran"] + languages=["ar"].

Response

FieldTypeDescription
querystringEcho of the input query.
resolved_entitiesEntity[]Buddhist entities recognised in the query (if any).
passagesPassage[]Ranked passage chunks. See Passage schema below.
search_accountsintegerNumber of corpus database shards searched.
latency_msintegerServer-side search latency in milliseconds.

Passage schema

FieldTypeDescription
chunk_idintegerInternal database chunk ID.
textstringThe passage text.
referencestringHuman-readable reference (e.g. "Ch. 3 v. 5", "MN 10", "Surah 2:255").
sutta_idstringExternal document ID within the corpus (use with /v1/text/{uid}).
title_englishstringEnglish title of the source text.
title_palistringPali title (Buddhist texts only).
traditionstringTradition code (e.g. "hinduism", "islam").
languagestringLanguage of the passage text.
collectionstringCollection grouping within corpus.
translatorstringTranslator name, if applicable.
corpusstringCorpus code (use this value in corpus_codes filter).
urlstringSource URL for the text, if available.
scorefloatRetrieval score (RRF + entity boost). Higher = more relevant.

Answer

POST /v1/answer Starter + Professional only • Auth: required

Retrieves relevant passages then generates a cited, grounded answer via Claude Sonnet. Citations reference passage numbers in the response.

Request body

FieldTypeDefaultDescription
questionstringrequiredNatural language question.
corpus_codesstring[]nullScope to specific corpora (same as /v1/search).
traditionsstring[]nullScope to tradition(s).
languagesstring[]nullLanguage filter.
max_passagesinteger6Max passages to retrieve for context (1–10).

Response

FieldTypeDescription
questionstringEcho of the input question.
answerstringCited answer text. Citations appear as [1], [2], etc.
citationsCitation[]Source metadata for each referenced passage.
passages_usedstring[]First 200 characters of each passage provided as context.
latency_msintegerTotal latency including Claude generation.
Answer quality note The answer model (Claude Sonnet) is instructed to synthesise only from retrieved passages. It will explicitly state when the retrieved passages do not answer the question rather than hallucinating. For best results, scope the query to the relevant tradition(s).

Get Entity

GET /v1/entity/{id} All tiers • Auth: optional

Returns metadata and multilingual name variants for a Buddhist entity. Entity IDs appear in the resolved_entities field of search responses.

Buddhist entities only The entity recognition layer currently covers Buddhist canonical entities (suttas, figures, concepts). Non-Buddhist queries return an empty resolved_entities array.

Filtering & Scoping

Scope filters can be combined. They apply with AND logic — specifying both traditions and languages returns results that match both.

Priority order (most to least specific)

  1. corpus_codes — exact corpus identifier. Use when you know exactly which text(s) to search.
  2. traditions — searches all corpora within a tradition. Use for cross-text queries within a tradition.
  3. languages — filter by text language. Useful for requesting original-language results.
  4. No filter — searches all traditions and corpora (excluding opt-in GRETIL).

Python SDK

Install
pip install sourcetruth
Basic usage
from sourcetruth import Client

client = Client(api_key="st_your_key_here")

# Search
results = client.search(
    "What does the Quran say about mercy?",
    traditions=["islam"],
    top_k=5,
)
for r in results:
    print(f"[{r.corpus}] {r.reference}: {r.text[:120]}...")

# Grounded answer (Starter/Professional)
answer = client.answer(
    "What is the Buddhist concept of non-self?",
    traditions=["theravada"],
)
print(answer.answer)
for cite in answer.citations:
    print(f"  [{cite.index}] {cite.title_english} — {cite.reference}")

# Discover corpora
for corpus in client.corpora():
    print(f"{corpus.code}: {corpus.name} ({corpus.tradition})")

MCP / Claude Integration

SourceTruth is available as an MCP (Model Context Protocol) server on Smithery.ai. This enables direct integration with Claude, Claude Code, and any MCP-compatible AI assistant.

Two available tools

  • search_canonical_texts(query, traditions?) — retrieve relevant passages
  • answer_from_canonical_texts(question, traditions?) — grounded Q&A with citations
claude_desktop_config.json
{
  "mcpServers": {
    "sourcetruth": {
      "command": "uvx",
      "args": ["sourcetruth-mcp"],
      "env": {
        "SOURCETRUTH_API_KEY": "st_your_key_here"
      }
    }
  }
}

Known Limitations

  • Upanishads Part II (Brihadaranyaka, Chandogya, Mundaka Upanishads): currently stored as a single document block. Queries targeting these specific texts specifically by name return no results. Other Upanishad queries work normally.
  • GRETIL corpus: IAST Sanskrit transliteration cannot be aligned with English queries under voyage-multilingual-2. Excluded from unscoped search. Use explicitly with corpus_codes=["gretil"] only if supplying Sanskrit query terms.
  • Tibetan Buddhist: Only the Bardo Thodol (290 chunks) is indexed. Source-level retrieval scores 1.0 but chunk diversity is limited.
  • Mahabharata: Only partial coverage (569 chunks of the Ganguli translation — 3 Parvas). Full Ganguli ingestion is planned.
  • Entity recognition: Buddhist entities only. Searching for non-Buddhist named entities (e.g. Aristotle, Moses, Muhammad) does not trigger entity boost, but semantic search still retrieves relevant passages.
  • FTS (keyword search): Disabled for Arabic (Quran), Pali, Classical Chinese, IAST Sanskrit, and Gurmukhi corpora — vector search only for these languages.
  • Daily quota: Resets at UTC midnight. The 429 "Daily request limit reached" response persists until reset.
